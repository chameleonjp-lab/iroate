## 今回の修正

- 確定スコアのUUID別台帳は全文保存/読み戻し確認後に送信。quota/拒否時は同画面に同UUIDを保持し、未保存を15言語で警告。再試行で保存が回復してから送信。ゲスト/リタイアは公開スコアに転用しません。
- 受理済みtombstoneを保持し、同時タブ/逆順応答・複数未送信・不確実ACKを区別。破損JSON・キーとUUIDの不一致・同UUID異payloadは原文を消さず隔離/競合扱い。既存資料の「受理UUID削除」は旧実装であり、現在は受理済み台帳を残します。
- 正常RPC transportの1行配列・9列・名前・integer記録を検証。過去のsigned first/bestを維持。旧非冪等RPCへfallbackしません。サーバーのbtrim正規化契約に合わせ、名前の正規化を勝手に追加しません。
- 復元は確定時間>=0、非負整数miss、penalty=miss×5、送信点=丸めた総秒×100、対応言語、正常終了のresultState、自己ベスト表示値を検証。破損をクリア表示せず、原資料を削除しません。受理済み台帳は結果復元の対象ではありません。
- 匿名開始専用キュー/RPCを保持。保存キーと本文UUIDの違う記録を送信せず、生成UUIDと既存記録が衝突した場合は旧原文/恒久失敗を保持して代替送信しない最小修正のみで、匿名回数を公開ランキングへ変えません。
- 上位一覧はrank・名前・整数点数のshapeを検証し、壊れたHTTP200を空の成功にしません。既存順序/同点順位を維持。
- 音声の部分生成失敗、oscillator切断例外でもgainを後片付け。statechange通知より先にinterrupted復帰しても、resume前に古いvoiceを停止。master gainの一時初期化失敗も次の操作で再試行し、未初期化のままunlock成功にしません。既存音源・イベント・音量・保存オフ/0を保持。
- SafariのIME確定Enter/keyCode229で開始しない。自己ベスト保存はsetItemだけでなく原文読戻一致を確認して成功を表示。
- buildの旧出力は削除せず`.build-backups`へ退避してから新distを作成。公開対象は従来の静的成果物だけ。テスト/履歴/制御情報は含めません。
